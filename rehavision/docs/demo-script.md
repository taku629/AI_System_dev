## デモ① 歩行訓練（1分30秒）

**押すのは「訓練を開始」の1回だけ。** あとは自動で進むので、画面に合わせて話す。

| 画面の動き | 話すこと |
|---|---|
| 「本日の目標 5歩」が床に出る | 天井カメラとLiDARで動作を計測し、床に目標を投影します |
| 足跡が光り、歩数が 1→2 と増える | 患者はこのガイドに沿って歩くだけでよく、迷いません |
| **2歩目で安定度が46%に落ち、警告が出る** | ここで左足の踏み出しの乱れを検知しました |
| 右の判定が緑・黄で並ぶ | 1歩ごとの判定が自動で記録されます |
| 3〜5歩目で安定度が回復（91%） | 後半にかけて安定してきたことが数値で分かります |
| 「前回3歩 → 本日5歩」「次回目標 7歩」 | 回復が数値で可視化され、次回の目標も自動で提案されます |

**言い切りたいこと**（2つだけ）
- 患者：迷わず正しい動作ができる
- 作業療法士：**記録が自動で残る**＝記録作成業務の負担が減る

> 実機（カメラ・LiDAR・プロジェクター）は用意できていないため、
> **「投影される内容をソフトで再現しています」と先に断っておく。**
> 隠すと質疑で崩れる。先に言えば実現性の質問に落ち着いて答えられる。

## デモ② AI対話（2分）

**審査員にその場で質問してもらう。** これが課題の評価ポイント
「ハルシネーションを起こさない対話システム」への直接の回答になる。

1. 「何かご質問をいただけますか」と振る
2. **聞き取った質問を復唱**してから `question` に入力
   （聞き間違い防止＋他の参加者にも質問内容が伝わる）
3. セルを実行 → 回答が出る
4. セクション5を実行 → **音声が再生される**

想定質問は [`../prompts/07_testset.md`](../prompts/07_testset.md) の20問。

### 山場：RAGあり／なしの比較

質問が出なかった場合や、時間が余った場合はこれを見せる。

**「作業療法士の記録を確認して」** を2条件で比較する。

| 条件 | 応答 |
|---|---|
| RAGなし | 日時「本日10:00」、担当「OT〇〇」、本人の発言「早く家で料理がしたい」… **すべて実在しない** |
| RAGあり | 歩行訓練を実施し、バランス能力に改善傾向。更衣は自立に近い（＝参照情報どおり） |

> 参照情報を与えないと、LLMは存在しない診療記録を自信満々に作ります。
> 医療で使う以上ここが最大のリスクで、RAGでこれを潰しました。

## まとめ（1分30秒）

評価結果の数値を出す。詳細は [`evaluation.md`](./evaluation.md)。

| 指標 | RAGなし | RAGあり |
|---|---|---|
| Key Index Coverage | 0% | **76.9%** |
| Error Insertion率 | 12.3% | **0%** |

ルーブリック評価 **80/100点**。

最後に価値を3者で締める。

- 患者：動きが分かる／回復を実感できる
- 作業療法士：記録・説明の負担が減る
- 家族：回復状況を分かりやすく把握できる

## 質疑（2分）への備え

課題資料が「確実に抑えること」としている3点は必ず聞かれる。

1. **誰が使うのか**
2. **誰が払うのか**
3. **いくらかかるのか**

想定質問の一覧と回答の組み立ては [`qa-prep.md`](./qa-prep.md) にまとめてある。

実機がない点は正直に答える。「投影内容とAIの応答部分を先行して検証しました」と、
**何を確かめて何が未検証かを線引きして話す**ほうが信頼される。
