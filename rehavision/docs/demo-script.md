# プレゼン台本（本番7分想定）

課題資料「プレゼン時間と内訳」（管理担当Aが発表、7分＋質疑2分）に沿って、
`demo-ui`（歩行訓練プロジェクション）と `notebook`（Gemini対話デモ）を接続する構成案。
実際の時間配分・話者はチームで調整すること。

## 全体の流れ（目安 7分）

| 時間 | パート | 使うもの |
|---|---|---|
| 0:00-1:00 | 課題・背景説明 | `docs/concept.md`（背景・課題スライド相当） |
| 1:00-2:00 | Rehavisionの仕組み説明 | 企画スライド（システム概要図） |
| 2:00-3:30 | **デモ①：歩行訓練プロジェクション** | `demo-ui/index.html` |
| 3:30-5:30 | **デモ②：AI対話（審査員質問→回答→TTS）** | `notebook/rehavision_demo.ipynb` |
| 5:30-7:00 | 価値・Project提案のまとめ | Value/ターゲットスライド相当 |

## デモ①：歩行訓練プロジェクション（`demo-ui`）

**見せたいポイント**: 天井カメラ・LiDAR・床面投影によって、患者が迷わず動作できること／
リアルタイムのフィードバックがあること。

1. `rehavision/demo-ui` で `python3 -m http.server 8000` を起動し、ブラウザで開いておく（発表前に接続確認）
2. 「訓練を開始する」ボタンを押す
3. 画面左（床面投影の再現）で、目標提示 → 歩数カウント（0→5）→ 2歩目のAIフィードバック
   （「左足の踏み出しが少し不安定です！」）→ 終了メッセージ（「前回よりスムーズに歩けました！
   次回目標：7歩」）の流れをそのまま見せる
4. 画面右（作業療法士向けタブレット）に、AIが記録メモをリアルタイムで残していく様子を見せる
   → 「情報検索・記録作成業務の効率化」という価値訴求につなげる

## デモ②：AI対話デモ（`notebook`）

**見せたいポイント**: ハルシネーションを起こさない対話システムを、審査員の質問その場で確認できること。

1. Colabで `rehavision_demo.ipynb` を開いておき、セットアップ（セル1-3）は事前に実行しておく
2. 審査員に質問してもらう（例：「田中さんはコーヒー飲めますか？」「歩行訓練の進み具合は？」など）
3. 「4. 質問応答デモ」セルの `question` に審査員の発話をその場で入力し、実行
4. `ask_custom_llm` のログ（モデルのフォールバック挙動）をあえて見せることで、
   クォータ超過等の実運用課題にも対応済みであることを示す
5. 「5. TTSで読み上げ」セルを実行し、音声で回答を再生する
6. 想定外の質問（例：「田中さんは今日何を食べましたか？」）を1つ試し、
   「記録には情報がありません」と断定を避けて回答することでハルシネーション対策を示す
   （`prompts/woz_corpus_starter.md` の行7-8を参照）

## 質疑応答（2分）への備え

  （実現性・儲ける仕組み）に関する質問が来ることを想定し、事前に回答を用意しておく
- 実機（カメラ・LiDAR・プロジェクター）の代わりにソフトウェアでデモしている旨は、
  正直に前置きしておくと質疑がスムーズ
