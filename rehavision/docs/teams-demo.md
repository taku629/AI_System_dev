# オンライン（Teams）でのデモ手順

発表がTeams越しになる場合、対面とは詰まる箇所が変わる。特に**音声**は設定を1つ忘れるだけで
審査員に全く聞こえなくなり、課題要件の「音声ファイルを再生してください」を満たせなくなる。

## 対面との違い（3点）

| | 対面 | Teams |
|---|---|---|
| 音声 | スピーカーから出せば聞こえる | **設定しないと相手に届かない** |
| 画面 | プロジェクタに映すだけ | 共有するウィンドウの選択を誤ると見せたくない画面が映る |
| 通信 | ローカルは影響なし | 回線が細ると画面共有とAPI呼び出しが同時に詰まる |

---

## 1. 音声を相手に届ける設定（最重要）

Teamsの画面共有では、**「コンピューターサウンドを含む」をONにしないと、PCから出る音は相手に届かない。**
自分のスピーカーからは鳴っているので、**本人は失敗に気づけない**。ここが一番危ない。

### 手順

1. Teamsの「共有」ボタンを押す
2. 共有内容を選ぶ画面で **「コンピューターサウンドを含む」にチェック**
3. 共有を開始する

### 注意

- **全画面（デスクトップ）共有のほうが確実**。ウィンドウ単位の共有だと、Teamsのバージョンによっては
  音声が乗らないことがある
- Web版Teamsは音声共有が制限される場合がある。**デスクトップアプリを使うこと**
- ブラウザのタブ共有（Chrome）なら「タブの音声を共有」という別のチェックがある

### 事前テスト（必須）

**本番と同じPC・同じ共有方法**で、以下を必ず試す。

1. 班員を1人Teams会議に入れる
2. 画面共有（コンピューターサウンドON）を開始
3. Colabで音声を再生する
4. **相手に「聞こえた？」と確認する**

これをやらずに本番に臨むと、かなりの確率で無音になる。

## 2. 画面共有の構成

### 発表本番（デモ①②）

**全画面共有＋コンピューターサウンドON** を推奨。

事前にやっておくこと：

- [ ] 不要なブラウザタブ・アプリを閉じる
- [ ] OSの通知をオフにする（Windows: 集中モード／Mac: おやすみモード）
- [ ] Teamsのチャット通知もオフ（共有中にポップアップが映り込む）
- [ ] デスクトップの見られたくないファイルを片付ける
- [ ] Colabは**セル1〜3を実行済み**の状態にしておく（本番でのセットアップ待ちを無くす）
- [ ] 歩行訓練デモのページを別タブで開いておく

### タブの並び順（おすすめ）

```
[1] 歩行訓練デモ    [2] Colab    [3] 評価結果（スライド or evaluation.md）
```

デモ①→②→まとめ の順に、タブを左から右に移動するだけで進行できる。

## 3. 役割分担

オンラインは1人で全部やると詰まりやすい。分けたほうがよい。

| 役割 | やること |
|---|---|
| 共有役 | 画面共有を開始・切り替える。通知の管理 |
| 発表役 | 話す。管理担当Aが担当（課題資料スライド12） |
| 操作役 | Colabに審査員の質問を打ち込み、セルを実行する |
| 記録役 | 審査員のフィードバックをメモ（課題資料スライド11） |

**共有役と操作役は同じ人**が楽（共有している画面をそのまま操作できる）。
発表役が別の人なら、「次、質問を入れてください」と声で合図する段取りを決めておく。

## 4. 通信が不安定なときの保険

Teams通話中は画面共有が帯域を食うため、Gemini APIの応答が遅くなったり失敗することがある。
**7分の発表中に無言の待ち時間が生まれるのは致命的**なので、保険を用意しておく。

### 保険1：音声を事前生成しておく（推奨）

Notebookのセクション7で、想定質問の回答と音声（mp3）をまとめて生成できる。
本番前に実行してダウンロードしておけば、APIが落ちてもファイル再生でデモを続行できる。

### 保険2：デモの録画を撮っておく

デモ①②を通しで画面録画（音声込み）しておく。最悪、録画を再生する。
「ネットワークの都合で録画を流します」と断れば、デモとして成立する。

### 保険3：回答テキストだけでも見せる

音声が届かない事故が起きた場合、**Colabの出力テキストは画面共有で見えている**。
「音声が届いていないようなので、読み上げます」と言って発表者が読む。
完全な失敗にはならない。

## 5. WOZ収録をオンラインでやる場合

WOZは「ユーザ役がオペレータを見ない」ことが前提（課題資料スライド32）。
オンラインだと、これはむしろ**簡単に実現できる**。

### やり方

1. **オペレータのPCで両方の画面を開く**
   - `operator.html`（自分用）
   - 「ユーザ役用ディスプレイを開く」で `display.html` を別ウィンドウに
2. Teamsで **`display.html` のウィンドウだけを共有**（ウィンドウ単位共有）
3. ユーザ役は共有された画面を見ながら、Teamsで発話する
4. オペレータは手元の `operator.html` で応答を選んで送信

`operator.html` は共有していないので、ユーザ役には見えない。
2画面の同期はオペレータのPC内で完結するため、**この構成なら問題なく動く**。

> ⚠️ ユーザ役とオペレータが**別のPC**で `operator.html` / `display.html` を開いても同期しない。
> 必ずオペレータのPCで両方を開き、ディスプレイ側だけを共有すること。

### 録音

Teams会議には**レコーディング機能**があるので、それで収録すれば書き起こしが楽。
（補足資料スライド13では「スマホ等で録画or録音」を推奨しているが、オンラインなら会議録画で代用できる）

## 7. オンラインならではの注意

- **マイクのミュート管理**。デモ中に生活音が入ると集中を削ぐ
- **画面共有の切り替えに数秒かかる**。7分の中で何度も切り替えないよう、タブ移動で済ませる
- **アニメーションはコマ落ちする**。歩行訓練デモは1歩1.1秒とゆっくりなので問題ないが、
  回線が悪いと飛ぶことがある。焦らず「今、2歩目で不安定という判定が出ました」と口頭で補う
- **審査員の質問が聞き取りにくいことがある**。復唱してから入力すると、
  間違いも防げるし、聞いている側にも質問内容が伝わる
