# WOZ収録ツール

Wizard of OZ方式で対話コーパスを収集するためのツール。
課題資料のスライド32（オペレータ／ユーザ役の分離）・スライド38（頻出フレーズの貼り付け）・
スライド33-34（対話コーパスへの書き起こし）に対応している。

画面は2枚あり、別ウィンドウで開いて同期させる。

| 画面 | 誰が見るか | 役割 |
|---|---|---|
| `display.html` | **ユーザ役** | AIの応答が表示される。待機／確認中／応答の3状態 |
| `operator.html` | **オペレータ役のみ** | 応答を選んで送信する。ユーザ役に絶対に見せない |

## 起動

```bash
cd rehavision/woz-tool
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000/operator.html` を開き、
右上の**「ユーザ役用ディスプレイを開く」**を押すと別ウィンドウで `display.html` が開く。
そのウィンドウをユーザ役側のモニタ（またはタブレット）へ移動して全画面表示にする。

> `file://` で直接開くと2画面が同期しない。必ずHTTPサーバ経由で開くこと。

## 収録の進め方

### 準備

1. **座席配置**: ユーザ役はオペレータを見ない位置に座る。ディスプレイ画面だけを見る（スライド32）
2. **没入用素材**: リハビリ現場の写真・動画を用意し、見せながら発話してもらう
3. **録画・録音**: スマホで撮っておくと書き起こしが楽（補足資料スライド13）
4. **頻出フレーズの確認**: `phrases.js` の内容がシーンに合っているか確認。合わなければ書き換える

### 本番

1. ユーザ役が発話する（例：「リハビリの効果は出ている？」）
2. オペレータは**「確認しています…」を表示**を押す（考える時間を稼げる。実システムらしさも出る）
3. 左の**頻出フレーズをクリック**して応答を組み立てる。無ければ応答欄に直接入力
4. 「ユーザ役の質問」欄に聞き取れた範囲でメモ（**後から表で編集できるので、急ぐ必要はない**）
5. **送信して読み上げ**（`Ctrl+Enter` でも可）→ ディスプレイに表示され、音声で読み上げられる
6. 1行が対話コーパスに自動追加される

### 収録後

- 表の**質問・応答・カテゴリのセルは直接編集できる**。録画を見ながら質問を正確に書き起こす
- カテゴリを整理する（後でカテゴリごとにPrompt Templateの回答フォーマットを書き分けられる）
- **CSV出力**でExcelに取り込む（BOM付きなので文字化けしない）
- **JSON保存／読込**でセッションを跨いで作業を再開できる

記録はブラウザのlocalStorageにも自動保存されるため、誤ってリロードしても消えない。

## 音声について

ブラウザ内蔵の音声合成（Web Speech API）を使うので、**VOICEVOX等の1日あたり文字数制限がない**。
ただしOSに日本語音声が入っていない場合は使えず、画面に警告が出る。

その場合の選択肢：

- OSに日本語音声を追加する（Windows: 設定→時刻と言語→音声認識／macOS: システム設定→アクセシビリティ→読み上げコンテンツ）
- 「読み上げる」のチェックを外し、[VOICEVOX](https://www.voicevox.su-shiki.com/multiple) や
  [ondoku3](https://ondoku3.com/ja/) で作った音声ファイルを手動で再生する
  （※これらは1日に生成できる文字数に上限があるので注意）

本番前に必ず音声が出るか確認しておくこと。

## シーンを変えるには

`phrases.js` を編集する。

- `PHRASE_GROUPS`: 頻出フレーズ。グループ単位でカテゴリを持つ
- `CORPUS_CATEGORIES`: 対話コーパスに割り振るカテゴリの選択肢
- `operator.js` の `CATEGORY_HINT`: フレーズのグループから、コーパスのカテゴリを自動選択するための対応表

現在の内容は `../prompts/07_reference.txt`（患者：田中一郎）に基づく。

## Rehavisionで取れるシーン

1. **作業療法士 → タブレット**: 訓練前に患者情報を確認する場面
2. **家族 → 音声UI**: 面会に来た家族が回復状況を聞く場面

6人なら「ユーザ役1・オペレータ1・モデレータ1・記録2〜3」で、役を交代しながら複数セッション回せる。
モデレータやオペレータが「これも聞きたくなるな」と思いついた発話もコーパスに加えてよい（補足資料スライド13）。

## 収集したデータの使い道

課題資料スライド31・35の通り、対話コーパスは3つの用途がある。

1. **価値創造活動** — 実際にシステムを作る前に、対話の価値を体験して企画を修正する
2. **RAGデータ** — `../prompts/07_reference.txt` に不足している情報を洗い出す
3. **評価データ** — `../prompts/07_testset.md` に、机上では出てこなかった質問を追加する

特に3つ目が重要で、既存のテストセット20問は机上で作られた整った表現が中心。
WOZで得られる崩れた実際の言い回しを加えると、評価の説得力が上がる。
